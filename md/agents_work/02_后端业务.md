## 2. 服务入口与路由

### 2.2 路由注册 `src/router.ts`

- `enforceResourceIsolation`(`resourceIsolation.ts:399`)：**资源隔离核心安全中间件**。
  - 从 body/query 提取 `projectId/worldId/chapterId/sessionId`(`collectProjectIds` `196`)。

## 3. 核心游戏引擎（NarrativeOrchestrator + SessionService）

### 3.1 编排器 `NarrativeOrchestrator.ts`（先决定「谁说话/动机」，再生成台词）
- `runNarrativePlan()`(`4754`)：预加载 worldBook 后调 `doRunNarrativePlan`。
- `doRunNarrativePlan()`(`4822`)：准备角色/phase/事件/turnState，构造 Prompt(`buildOrchestratorPromptPayload` `3902`)，**规则编排优先**，否则用编排模型(`storyOrchestratorModel`)决定 who/motive/awaitUser(`buildAiNarrativePlanResult` `4094`)。
- `runStorySpeakerContent()`(`4358`)：按编排结果生成具体台词。
- `runNarrativeOrchestrator()`(`5024`)：串联 plan + 台词生成。
- 状态回写：`applyOrchestratorResultToState()`(`5832`)、`applyMemoryResultToState()`(`5564`)、`triggerStoryMemoryRefreshInBackground()`(`5776`)。

### 3.2 会话服务 `SessionService.ts`（回合流转与落库）
- `orchestrateSessionTurn()`(`3804`，带 `withSessionLock`)。
- `orchestrateSessionTurnInner()`(`3825`)：加载 session/world/state/近期消息、同步章节进度事件、推进世界时钟、持久化 stateJson、章节切章逻辑、任务模式判定(`tryBuildTaskModePlan` `1369`)、章节结束判定(`runConcurrentSessionJudgeAndNarrative` `1911`)。
- `commitSessionNarrativeTurn()`(`4732`) / `commitSessionNarrativeTurnInner()`(`4740`)：落库 `t_sessionMessage`、章节完成判定、turnState 推进、快照持久化、参数卡刷新(`scheduleSessionRoleParameterCardRefresh` `2256`)。

### 3.3 路由层编排入口
- `routes/game/orchestration/index.ts:962` `router.post("/")` → `handleDebugOrchestrationRequest`(`830`)：有 `sessionId` 直接 `orchestrateSessionTurn`(`833`)，否则走调试态(`handleInitialDebugTurn` `379`/`handleDebugPlayerTurn` `632`)，并发「章节判定 + 候选编排」(`runConcurrentDebugJudgeAndNarrative` `499`)。**编排接口只返回 `role`/`roleType`/`motive`，其他走 `storyInfo`**。
- 台词落库：`routes/game/commitNarrativeTurn.ts:13` → `commitSessionNarrativeTurn`。

### 3.4 一轮对话流转（详见 `00` §4 时序图）
```
用户前端输入 → POST /game/orchestration
  ├─ 无 sessionId → 调试态(handleInitialDebugTurn/handleDebugPlayerTurn) + 并发(章节判定+候选编排)
  └─ 有 sessionId → orchestrateSessionTurn(SessionService:3804)
        → orchestrateSessionTurnInner(3825)：加载上下文/同步进度/推进时钟
        → runNarrativePlan(NarrativeOrchestrator:4754)
              → doRunNarrativePlan(4822)：规则分支优先；否则 storyOrchestratorModel 决定 who/motive/awaitUser
        → 返回(仅 role/roleType/motive)
前端拉取台词与语音(storyInfo/streamvoice)
  → POST /game/commitNarrativeTurn → commitSessionNarrativeTurn(4732)
        → 落库 t_sessionMessage / 章节完成判定 / turnState 推进 / 参数卡刷新
```

## 5. `src/lib/fixDB.ts` — 数据库迁移 / 种子

> 不是版本化迁移框架，而是**全量幂等手工补丁**模式——无版本表，每次启动全量跑，每个操作自带 if-exists 判断。

- 入口：`export default async (knex: Knex): Promise<void>`(`68`)。
- 安全封装：`ensureTable`/`addColumn`/`dropColumn`/`alterColumnType`(`97` 起)。
- **种子数据**：模型清单(volcengine/lmstudio/autodl_chat 等)；Prompt 模板默认值从 `src/lib/fixDB.prompts.ts` 导入(`52`)。
- 与游戏状态存储关系：它保证表与字段存在；运行时状态(session/world/state)由 `gameEngine.getGameDb()` + `t_session`/`t_storyWorld` 等承载，`fixDB.ts` 不负责逐回合状态读写。

- `ensureWorldRolesWithAiParameterCards()`(`418`，导出)：写入 `parameterCardJson`，持久化到 `t_storyWorld`。
- 读取/展示：随 world 返回前端；运行时刷新由 `SessionService.scheduleSessionRoleParameterCardRefresh`(`2256`) 触发。

## 8. 立绘与图像处理

### 8.1 生图 `src/routes/game/generateImage.ts`
- `router.post("/")`(`63`)：参数 `type: "role" | "scene"`。
  - 从 `storyImageModel`/`editImage`/`assetsImage` 选配置。
  - 调 `u.ai.image({systemPrompt, prompt, imageBase64, size, aspectRatio})`(`119`)。
  - 存 OSS：`/${projectId}/game/${type}/${uuid}.jpg`，并保存 `_original.jpg`(`145`)。

### 8.2 本地人像抠图 `src/lib/localAvatarMatting.ts`
- 常量：`LOCAL_BIREFNET_MANUFACTURER="local_birefnet"`(`9`)/`LOCAL_MODNET_MANUFACTURER="local_modnet"`(`10`)；默认模型 `birefnet-portrait`(`11`)/`modnet-photographic-portrait`(`12`)。
- `installLocalBiRefNet()`(`601`)：装 BiRefNet/MODNet(ONNX+onnxruntime)。
- `runLocalBiRefNetMatting()`(`760`)：生成 `run_birefnet.py`/`run_modnet.py` 调用，输出**透明前景 PNG**(即 avatar)。

### 8.3 立绘三类（origin / background / avatar）的产生与存储
| 类型 | 含义 | 产生 | 存储 |
|---|---|---|---|
| **origin** | 角色/场景原始图 | `generateImage.ts`(`type:"role"\|"scene"`)，存 `_original.jpg` | OSS `/{projectId}/game/{type}/{uuid}.jpg` |
| **avatar** | 透明前景立绘(抠图) | `localAvatarMatting.ts` 从 origin 抠图，或 `separateRoleAvatar.ts` 路由触发 | 透明 PNG |
| **background** | 场景背景图 | `generateImage.ts` 以 `type:"scene"` 生成 | OSS `/{projectId}/game/scene/...` |

> 关系：**origin 是源头 → avatar 是 origin 经本地抠图得到的透明前景；background 即场景类 origin**。三者落在 OSS `/{projectId}/game/` 命名空间，由 `projectId` 隔离。
